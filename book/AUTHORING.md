# Authoring guide for "From Python to SASS"

The book explains how tinygrad 0.14.0 (commit `6f87158d77f66a36d5f8bbe915170b24e2acabe8`) lowers Python
`Tensor` code to CUDA C, PTX and SASS on an NVIDIA L4 (sm_89), with PyTorch (eager and `torch.compile`)
side by side. It is static HTML: open `book/index.html` in a browser, no server needed.

## Ground rules

- **Every number, kernel name, line of IR, source, PTX and SASS shown comes from the captures** in
  `book/data/` (made on the L4 by `harness/run_all.py`), loaded through the widgets below. Don't type
  assembly or kernel names from memory. When prose quotes a value (a kernel name, a time, a register
  count, an instruction), it must match the capture; read it from `book/captures/<example>/<variant>.json`.
- **Claims about tinygrad internals cite the source** at the captured commit with
  `<a class="src" data-src="tinygrad/codegen/__init__.py#L289"></a>` (the link text defaults to `path:line`).
  The source is checked out at `/tmp/src/tinygrad`. Check line numbers there.
- Claims about PyTorch come from the torch captures (PyTorch 2.14.1+cu130, Triton 3.8.0 on the L4).
- Explain like a good textbook: build intuition first (a diagram or animation), then show the real
  artifact, then point at the exact lines that matter. Short paragraphs.

## Files

- `index.html`, `chNN-*.html`: one page per chapter. Copy the skeleton below.
- `assets/book.css`, `assets/book.js`: shared; **don't edit them**. If you need a widget change, say so
  in your report. Chapter-only CSS goes in a `<style>` in the chapter's `<head>`.
- `assets/chNN.js`: the chapter's own animations and diagrams (optional). Use `BOOK.ready(fn)`.
- `data/*.js`: generated by `harness/build_data.py` from `captures/`. Don't edit.

| `<div class="torch-view" data-key="softmax/torch" data-tabs="eager,fx,pre,post,output,ttir,ttgir,llir,ptx,sass" data-tab="output"></div>` | PyTorch eager kernels and every Inductor/Triton stage |
| `<div class="bars" data-keys="matmul/noopt,matmul/default,matmul/torch:eager" data-labels="NOOPT|heuristic|cuBLAS"></div>` | animated time comparison |
| `<div class="sass-mix" data-key="matmul_fp16/default"></div>` | SASS instruction histogram |
| `<div class="code-compare" data-left="add_ptx/cuda|0|ptx" data-right="add_ptx/ptx|0|ptx" data-labels="NVRTC|tinygrad"></div>` | two artifacts side by side; tab is one of ast,uops,source,ptx,sass,ptxas |
| `<pre class="code static" data-lang="python">...</pre>` | static highlighted code (python, c, ptx, sass, uop, llvm, mlir). Escape `<` as `&lt;` |
| `.reveal` on any block | fades in on scroll |
| `.callout`, `.callout.warn`, `.callout.torch` | asides; `.torch` for PyTorch comparisons |

In `assets/chNN.js`, `BOOK.get(key)` returns a capture, and `BOOK.codeBlock(text, lang, {highlight})`,
`BOOK.highlight`, `BOOK.addedLines`, `BOOK.whenVisible(node, fn)`, `BOOK.fmtUs` are available. Draw custom
animations with inline SVG + CSS animations or `requestAnimationFrame`, with play/step buttons where the
reader should control the pace. Colors per stage: `var(--s-tensor|schedule|codegen|render|compile|run)`.

## Captures

Keys are `<example>/<variant>`; the tinygrad examples are defined in `harness/examples.py`.

| Example | Variants | tinygrad expression (shapes) |
|---|---|---|
| add | default, torch | `a + b` (1024×1024 f32) |
| fused_chain | default, torch | `((a*b + c).relu() * 2.0)` |
| gelu | default, torch | `a.gelu()` (tanh approximation) |
| transpose | default, torch | `a.T.contiguous()` |
| broadcast_add | default, torch | `a + b.reshape(1, 1024)` |
| pad_slice | default, torch | `a[::2, 1::3].pad(((1,1),(2,2))).contiguous()` (1000×1000) |
| permute4d | default, torch | `a.permute(0,2,1,3).contiguous()` (32⁴) |
| sum_rows | default, torch | `a.sum(1)` |
| max_cols | default, torch | `a.max(0)` |
| sum_all | default, torch | `a.sum()` (4096×4096) |
| softmax | default, torch | `a.softmax(-1)` |
| layernorm | default, torch | `a.layernorm()` |
| matmul | default, noopt (NOOPT=1), beam2 (BEAM=2), torch | `a @ b` (1024³ f32) |
| matmul_fp16 | default, no_tc (TC=0), torch | `a.matmul(b, dtype=float)` (2048³ f16 in, f32 out) |
| exp, sin | default, transcendental2 (TRANSCENDENTAL=2), torch | `a.exp()`, `a.sin()` |
| int_divmod | default, torch | `a // 7 + a % 10` (int32) |
| add_ptx, sum_rows_ptx, matmul_ptx | cuda, ptx (DEV=CUDA:PTX) | same as add / sum_rows / matmul |
| mlp_backward | default, torch | gradient of `(x @ w).relu().sum()` w.r.t. w (x 256×512, w 512×256) |
| jit | default | TinyJit over 4 calls + a symbolic-size kernel (special format, see captures/jit) |

A tinygrad capture has: `tinygrad_code`, `tensor_graph` (pyrender of the lazy graph), `passes` (stage,
name, kernel, nodes, changed, ms, ir), `kernels` (ast, name, global_size = grid in blocks, local_size =
threads per block, applied_opts, estimates, uops, source, ptx, ptxas_info, sass, sass_mix, regs, time_us),
`check` (vs numpy), `env`. A torch capture has `eager_kernels`, `inductor_kernels` (name, us),
`inductor_debug` (fx_graph, ir_pre_fusion, ir_post_fusion, output_code) and `triton_kernels` (ttir, ttgir,
llir, ptx, sass). Inductor sometimes compiled one kernel twice during autotuning; both copies are kept.

Notes on the data:
- For `DEV=CUDA:PTX` captures, `source` is tinygrad's PTX template with `VERSION`/`TARGET` still in it;
  the `ptx` field is the version that was actually loaded.
- `matmul/torch` has no Triton kernel: Inductor called cuBLAS (`extern_kernels.mm`).
- Times are the best of five runs, measured by tinygrad's DEBUG=2 timing (or torch.profiler for PyTorch).
